## 保持对话的节奏

有时候，你已经知道要继续追问，只是不想再把那句话敲一遍。

**DSH Next Message** 在助手正常回复结束后，根据当前对话预测你可能说的下一句话。在空输入框里，它是一条轻轻浮现的灰字；按下 **Tab**，它就变成可以修改的草稿。合适就用，不合适按 **Esc**，或者直接开始打字。

> **建议由模型生成，发送由你决定。** 采纳后可编辑、可撤销，插件始终不会替你发送消息。

## 小动作，少打扰

| 你需要的体验 | 插件如何配合 |
| --- | --- |
| **懂得接着聊** | 参考当前会话的近期上下文与用户约束，预测下一条用户消息 |
| **Tab 就能接上** | 整句采纳为可编辑草稿，支持原生撤销 |
| **自己打字优先** | 一旦开始输入就撤下建议，采纳前再次校验草稿状态 |
| **中文输入顺手** | 输入法组词、`/` 和 `@` 菜单期间不抢键盘操作 |
| **模型自由选择** | 默认跟随当前会话，也可单独选择 DSH 已配置的快速模型 |
| **该安静时安静** | 已有草稿、附件、引用、排队消息，或回合取消、失败时不生成建议 |

## 一分钟开始

1. [下载 **dsh-next-message-0.1.0.tgz**](https://github.com/746445568/dsh-next-message/releases/download/v0.1.0/dsh-next-message-0.1.0.tgz)。保留 `.tgz` 格式，**无需解压**。
2. 打开 DSH 的 **插件 → 添加插件**，输入安装包的完整本地路径，安装并启用。完整退出并重新启动 DSH。
3. 在 **设置 → 下一句预测** 中确认已开启，然后聊完一轮，保持输入框为空，等待灰字出现。

也可以使用现有的 `dsh` 命令。以 PowerShell 和 desktop profile 为例：

```powershell
dsh plugin --profile desktop add "C:\Downloads\dsh-next-message-0.1.0.tgz"
```

网页版使用对应的 `web` profile。若已安装其他灰字预测插件，先关闭它，避免同时接管输入框与 Tab。

**兼容目标：DSH 内核 `0.2.1-rc.1/rc.2`。** 实际在 `0.2.1-rc.2` 的 Linux / Chromium Web UI 验证；Windows/macOS 原生桌面壳与 rc.1 尚未实测。桌面应用版本与内核版本是不同字段，完整范围见[验证记录](docs/VALIDATION.md)。

## 三个操作就够了

| 操作 | 结果 |
| --- | --- |
| **Tab** | 填入整条建议，成为可修改的草稿；不发送 |
| **Esc** | 忽略本轮建议 |
| **直接打字** | 撤下建议，继续写你自己的话 |

切换会话或开始新回合会取消旧预测，迟到结果不会填进新会话。超时、生成失败或没有合适的后续内容时，本轮跳过，不在输入框显示错误条。

## 调成你喜欢的节奏

在 **设置 → 下一句预测** 中调整开关、模型、语言、等待上限、建议长度和上下文预算，点击“保存设置”后生效。

- **开箱即用的模型来源。** 默认使用当前会话实际选择的服务商与模型，采用该模型声明支持的最低思考档位。
- **可选独立快速模型。** 直接选择 DSH 已配置的模型，无需再给插件填写 API Key。
- **等待有上限。** 默认 3000 毫秒，可调整为 1000–10000 毫秒。超时本轮跳过，不自动连续重试。
- **减少重复请求。** 相同回合、上下文与模型配置只预测一次；成功、空结果和失败均缓存。更换设置后允许重新生成。

真实模型的响应时间与建议质量取决于服务商、模型和上下文，本项目不承诺固定延迟或命中率。

## 数据去哪里？

预测通过 **DSH 原生模型服务**进行，会把当前会话选取的近期文本发送给所选模型服务，按其正常费用或额度计费。插件没有单独的第三方 API 端点。

- 只处理当前会话，不读取其他会话；不执行工具、访问新网站或自动发送消息。
- 辅助请求前遮蔽常见密钥形状；这不等同于识别所有敏感信息，仍应按所选模型服务处理会话数据。
- 偏好保存在 `$DSH_HOME/next-message.json`，未设置时使用 `~/.dsh/next-message.json`；不保存对话或密钥。
- 请求数、采纳数、耗时和服务商返回的 token 统计仅保留在宿主内存中，重启清空。

<details>
<summary><strong>没有出现灰字？</strong></summary>

1. 在设置页确认已启用，模型来源可用，插件已连接。
2. 完成一轮新的正常回复，再清空输入框。执行中、取消或失败的回合不触发预测。
3. 查看“当前状态”。超时可增加等待上限或选择更快模型；模型失败时，先确认 DSH 自身能正常使用它。
4. 完整退出并重新启动 DSH，查看插件加载错误，并关闭其他预测插件。

## 开发与贡献

Node.js `^22.19 || >=24`。客户端使用 DSH 提供的 React，无新增运行依赖。

```sh
git clone https://github.com/746445568/dsh-next-message.git
cd dsh-next-message
npm run check
npm pack
```

| 入口 | 职责 |
| --- | --- |
| `lib/context.js` | 上下文裁剪、提示与输出检查 |
| `lib/engine.js` | 回合、模型、缓存与取消 |
| `lib/client-state.js` | 异步预测与草稿状态 |
| `src/client-entry.js` | 原生编辑器、键盘操作与设置 |

`client.js` 为生成文件，修改客户端后运行 `npm run build`。可复现的浏览器测试见 [qa/README.md](qa/README.md)。欢迎带着 DSH 内核版本、系统、模型名称和复现步骤提交 [Issue](https://github.com/746445568/dsh-next-message/issues)。请勿附带密钥或私人对话。
